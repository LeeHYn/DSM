# F-005 Product API Implementation Plan

> 실행: main agent가 executing-plans 순차 실행. 사용자 2026-09-04 전체 기획 출시 및 F-005/F-003/F-017 구현 요청을 승인 근거로 사용한다.

**Goal:** Task 생성/조회/수정/삭제/완료/취소, 일일·누적 점수, 기간별 랭킹을 기존 인증 API에 연결한다.

**Architecture:** 기존 authenticated-client를 안정적인 별도 Context로 노출한다. 인증된 사용자별 ProductStore가 resource별 loading/error/data와 요청 세대를 관리한다. prototype context는 theme/toast만 제품 화면에서 사용한다. 기존 RN UI를 유지하며 실제 응답만 표시한다.

**Tech Stack:** RN 0.83.10, React 19.2, TypeScript, 기존 fetch client, Jest. 신규 dependency 없음.

**Spec:** 이 계획의 아래 계약과 기존 `.ai/docs/2026-07-19-frontend-page-requirements.md`, Backend controller/Prisma 모델.

## 계약

- UTC `YYYY-MM-DD` 일자를 명시한다. 입력·표시 시간은 UTC로 명확히 표기하여 서버 score day와 일치시킨다. 날짜 이동과 앱 foreground 복귀 시 실제 데이터를 갱신한다.
- Task API의 LOW/MEDIUM/HIGH, PENDING/COMPLETED/CANCELLED, ISO timestamp, categoryId를 변환한다. category 목록은 GET /categories, 미분류는 categoryId 생략이다.
- score는 GET /scores?date= 및 /scores/summary, ranking은 GET /rankings?period=DAILY|WEEKLY|TOTAL 및 /rankings/leaderboard. null daily score만 0이다. 오류를 0 또는 가짜 순위로 대체하지 않는다.
- /auth/me는 nickname을 제공하지 않는다. 이름을 만들어 표시하지 않고 중립적인 인사/내 계정 문구를 사용한다. 점수·티어는 summary에서 읽는다.
- 응답은 unknown에서 runtime 검증한다. malformed, 부적절한 enum/date/number, 잘못된 사용자 응답은 안전한 오류로 처리한다.
- 병렬 resource read는 하나의 실패가 다른 성공을 숨기지 않는다. 날짜/기간 변경·refresh·mutation 후 오래된 read가 현재 화면을 덮어쓰지 않는다.
- mutation은 단일 in-flight로 중복 클릭을 차단하고 완료 토글/삭제를 optimistic 적용한다. 실패 시 이전 상태를 복구하고, 서버 적용 여부가 불명확한 network/timeout 실패는 재조회한다. POST 자동 재시도 없음.
- 성공 후 Task/score/summary/현재 ranking을 무효화·재조회한다. logout/계정 전환 시 store 폐기 및 pending 응답 차단. 세션 token은 store에 저장하지 않는다.
- 원장 FIXING은 승인된 구현 상태를 기록하며, 실기기/독립 recheck가 없으면 RECHECKED로 닫지 않는다.
